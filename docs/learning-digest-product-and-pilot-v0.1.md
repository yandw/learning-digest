# Learning Digest 产品与合作方案

**V0.1 · 合作讨论稿 · 2026 年 11 月 22 日**

Learning Digest 是面向长视频学习者的个人学习库。学习者在原平台看课，用 Chrome 侧栏记录进度、跟读逐字稿和做笔记，课后回到 Web 学习库继续学习或复习。首批试点建议邀请近期在 B 站、YouTube 等平台学习 AI、且已有使用 AI 辅助学习习惯的人，用他们本来就要学习的课程验证产品价值。

项目目前处于 Demo 迭代阶段。收藏、续学、转写与 AI 总结已有实现和部分实测记录，正式发布暂缓。本文中的试点安排、双方分工与后续功能供合作讨论。 [产品化规划](productization-four-part-plan-v0.1.md) · [发布验收记录](p0-release-acceptance-checklist.md)

## 一、设计理念

**围绕一门课保存学习过程。** 一门长课可能要分几次学完。学习库将进度、笔记、逐字稿和总结归到相应资料下。播放位置按实际视频来源记录，多分集各自续学。学过一段就可以复习，补学后可用新增材料再生成总结。

**沿用原平台，减少学习时的切换。** 用户用自己的平台账号打开课程，仍在原播放器观看。Chrome 侧栏承载边学边记、逐字稿和解释，Web 学习库承载收纳、续学入口和课后回查。平台有可用字幕且能力开启时优先使用字幕。需要语音转写时，由用户按浏览器提示授权采集所选标签页的音频。

**让 AI 结果能回到课程原文。** 将逐字稿、用户笔记和 AI 生成内容分别显示。课程总结基于当前归档的逐字稿和笔记，引用要能在已归档的原文中核对。来源支持定位时可回跳原视频，否则保留原文与时间信息。字幕缺失、转写等待或失败应按实际状态提示，方便用户判断材料覆盖范围。 [领域术语](../GLOSSARY.md) · [接口契约](../contracts/contract-v1.md)

## 二、功能设想

### 从收藏到复习

| 学习环节 | 用户体验 | 当前进展 |
| --- | --- | --- |
| 收藏与续学 | 在 Web 粘贴链接，或从插件收藏当前页。回到学习库后打开原来源，从上次位置继续，也可从头开始。 | Web 与插件均有收藏入口，受支持的视频来源已有进度与续学能力。普通网页可按链接收纳。 |
| 边学边记 | 在侧栏查看带时间戳的逐字稿，搜索或选中文本请求解释。可手写课程笔记，也可把逐字稿选文保存到课程，有有效来源位置时附上时间戳。 | 已实现字幕与语音转写两条路径。已有侧栏摘记保存、Web 回查和时间位置核对的实测记录。 |
| 回顾一次学习 | 学习中通过概览看已经学到的话题，结束后查看这次学习的纪要。纪要可独立阅读、打印或导出供个人复习。 | 侧栏已具备概览与纪要能力，纪要提供 HTML 和 Markdown 导出。 |
| 复习整门课 | 从课程详情查看资料来源、笔记、历次学习的逐字稿和课程总结。已有逐字稿时可主动生成总结，补学后可重新生成并回看历史版本。 | 真实 AI 总结有联调及回读记录，引用跳转与长课稳定性仍应按试点样本核对。 |
| 试点管理 | 通过邀请开通账号并关联插件。管理员按平台配置启用、字幕和语音转写能力，用户可查看服务用量。 | 邀请、插件关联、站点管理与用量已有实现。仓库验收环境使用开发验证码，外部试点的邮件方式需在启动前确认。 |

课程总结以一门课当前已有的材料为范围，学习纪要以一次学习会话为范围。首轮平台范围包括小鹅通、B 站、YouTube 和小红书。具体到某个视频，字幕读取、音频采集和进度定位依赖站点登录状态、轨道可用性、播放器能力与浏览器授权。验收记录已有字幕直归档、真实 ASR 和真实 AI 总结的样本证据，跨平台完整验收仍有待补项。 [中文 README](../README.zh-CN.md) · [发布验收记录](p0-release-acceptance-checklist.md)

### 下一步体验方向

- **让学习库更容易回到上次的课程。** 首页优先呈现可续学的资料，评审稿以标题列表为起点。跨课程笔记汇总、资料与笔记搜索列入后续体验验证。
- **让长课复习更可靠。** 优先核对字幕读取失败后的提示和回退、逐字稿时间轴与原视频的对应关系，以及长课总结的等待和失败重试体验。
- **用真实学习行为决定扩展范围。** 先观察用户是否会回来续学、收藏第二份资料、翻看逐字稿或使用总结复习，再讨论更多平台和课程整理方式。

## 三、合作开展方式

建议先与一个课程团队或学习社群做邀请制试点，使用少量经授权的长课样本。先约定验证问题、内容范围与部署责任，再邀请学习者体验。优先验证两件事：用户能否独立完成第一次收藏到复习，以及离开后是否愿意主动回来续学。

| 参与方 | 建议投入 |
| --- | --- |
| Learning Digest 项目方 | 提供 Demo、插件安装与账号开通指引，配置约定的站点及服务能力，协助联调，记录缺陷和使用反馈，整理试点复盘。 |
| 合作方 | 确认可处理的课程内容与授权范围，提供可播放的样本、必要的平台访问条件和试点对接人，邀请有真实学习需求的用户。 |
| 双方共同 | 确认部署与运维责任、验证码交付方式、模型账号和费用承担、内容使用与保留规则、反馈收集方式，以及进入下一阶段的条件。 |

### 试点步骤与验收

1. **对齐样本与环境。** 选定试点用户与代表性课程，至少覆盖可用字幕和需要且允许语音转写两种情况。逐条记录平台登录、播放定位和采集授权条件。若涉及多分集或受限课程，选一个有代表性的样本专项复核。
2. **用样本联调。** 固定试点版本，验证受邀登录、插件关联、收藏、续学、笔记回查、逐字稿归档与总结引用。使用两个独立账号检查资料隔离和退出行为。对照字幕样本检查是否跳过语音转写，对照 ASR 样本检查失败是否可识别，分别记录每个样本的结果。
3. **观察真实使用。** 请受邀用户用自己的学习任务过一遍流程，收集主动续学、第二次收藏和课后回查的实际反馈，同时记录安装、登录、定位和等待在哪一步让人放弃。记录可通过用户反馈和联调日志汇总，具体采集口径在试点前约定。
4. **共同复盘并决定是否扩大。** 核心链路按约定样本逐条可用，且确有用户主动回访续学或复习时，再评估扩大人群和平台范围。遇到核心阻断时，按样本、浏览器与版本记录问题，明确责任人和复测条件。试点周期、样本数量和通过阈值由双方启动前确定。

现有部署方式由使用方自行运行学习服务并在服务端配置模型密钥。合作试点需明确由哪一方部署和维护。启用云端服务时，音频或文本经所部署的后端交给配置的处理服务。试点前应核定处理权限、实际数据流向、保留及删除方式，并约定课程原文、笔记和纪要可以在哪些范围内导出或分享。 [隐私说明](../PRIVACY.md)
