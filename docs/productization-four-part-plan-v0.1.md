# Learning Digest 平台整合范围与接口 v0.1

状态：产品化开发规格草案。集成目标分支为 `productization/integration`，基线为包含最新 PoC 的 `9ebcf57`。

## 平台整合的三个开发单元

**一期分三轮开发，全部通过验收后统一发布（已确认）。** 每轮形成一段可独立联调和验收的流程。首批用户在完整链路交付后受邀试用。

| 开发轮次 | 可用单元 | 用户验收 |
| --- | --- | --- |
| 第一轮：收藏与续学 | 桌面 Web 学习库、已授权的插件和资料 API。 | 从四个平台收藏并打开原视频。在插件列表选择课程标签页，开始学习、保存进度和手写笔记，下次回来续学。 |
| 第二轮：字幕或音频转写与归档 | 插件读取并展示完整的可用字幕，或采集音频，由 API 调用转写 Worker，逐段展示返回的结果。两条路径将带来源时间戳的逐字稿按 Session 保存。 | 字幕可直接查看全文。ASR 以约 30 秒音频为一段，结果逐段出现，等待结果时显示「转写中」。两类逐字稿都归到对应资料，可在 Web 回查。 |
| 第三轮：按需生成课程总结 | 用户主动生成课程总结，使用该课程当前已有的逐字稿和笔记。课程可以尚未学完。 | 用户在课程未学完时点「生成总结」，成功后可看结果。补学后可主动再次生成。A、B 两门课的内容各自独立。 |

- 首批邀请近期在 B 站、YouTube 等平台学习 AI、已经习惯用 AI 辅助学习的人，使用自己的课程。完整试用时观察他们是否主动从学习库续学或收藏第二份资料，以及是否使用逐字稿和课程总结复习。
- 桌面 Web 和桌面 Chrome 插件是首版入口。任何能在桌面浏览器打开目标内容的 HTTP(S) 网页都可收藏，包括来自小红书、抖音和小鹅通的网页。移动版网页地址也可以使用。App 分享短链需要能到达同一内容的网页，首轮可以让用户打开目标网页后再保存实际地址。
- **首轮覆盖小鹅通、B 站、YouTube 和小红书（已确认）。** 四个平台都能收藏和打开。对于能在桌面网页播放并定位的视频，四站都验收记录播放位置、续播和手写时间戳笔记。普通网页和图文资料支持收藏、打开和手写笔记。抖音和其他网页首轮走通用收藏入口。
- **平台整合以原网页为入口（已确认）。** 学习库收藏原网页链接，保存资料信息、播放进度、手写笔记、字幕或音频转写生成的逐字稿，以及课程总结。观看、续播和回看均打开原平台。
- 私用 NAS 转写客户端及其文本导入、面向用户的录播文件上传和站内媒体存储另案讨论。

## 四个发布单元与原视频页面

本次链路包含四个自研发布单元和一个外部参与方。建议保留根目录作为扩展的打包入口，Web、API 和 Worker 分别放在 `apps/web/`、`apps/api/`、`apps/worker/`。接口和公共测试样例放在 `contracts/`。

| 工作 | 责任边界 | 单独验收 |
| --- | --- | --- |
| **原视频页面（外部）** | 用户在原平台用自己的账号访问课程并播放。用户在原视频页和插件中完成浏览器要求的采集授权。 | 能回到同一来源播放，插件在授权后才能开始采集该标签页。 |
| **Web 学习库** | 邀请登录、链接收纳、学习列表与详情、笔记和继续学习入口。第二、三轮展示逐字稿和课程总结。后续提供用量与账单界面。 | 验证收藏、查看笔记及新标签页打开。结束学习后能查阅该次逐字稿，课程总结能回查相关原文。 |
| **浏览器插件** | 首轮做账号关联、保存当前页、课程标签页选择、播放位置和时间戳笔记。第二轮从选定标签页读取字幕或采集音频，随 Session 和来源信息提交给 API。 | 验证四站续学、分集隔离、标签页锁定，以及字幕或音频始终归到选中来源的 Session。 |
| **后端 API** | 管理邀请和身份、资料与来源、Session、进度和笔记。第二轮接收字幕或采集音频，按需调度 Worker，统一保存逐字稿。第三轮提供课程总结的归属与查询。后续按账号记录转写与计算用量。 | 双账号隔离覆盖资料、笔记、逐字稿和总结。重复提交和断网重发保持结果一致。 |
| **录播转写 Worker** | 第二轮按 API 下发的任务处理采集音频，返回带时间戳的转写结果及处理状态。 | 用可区分的 A、B 音频验证逐字稿归属、失败反馈和重试一致性。 |

## 跨端共享的数据

PoC 以 Session 为入口，产品化增加资料和来源两个稳定标识。已确认的术语见 [GLOSSARY.md](../GLOSSARY.md)，其他接口名称暂作草案。

| 数据 | 最小字段或关系 |
| --- | --- |
| 学习资料 `Resource` | `id`、`title`、`kind`。可代表一个独立网页或课节，归属于当前账号。专题与有序课程归组可在验证收藏和续学后补齐。 |
| 来源 `Source` | `id`、`resourceId`、`kind` 和原始网页地址。网页来源按下文规则匹配。 |
| 听课与进度 | `Session` 关联实际学习的 `sourceId`。续播进度按账号与来源保存，包含 `positionMs` 和 `revision`。同一个课节可有多个来源和多个 Session。 |
| 笔记 `Note` | `id`、`resourceId`、`text`，以及可选的 `sourceId`、`positionMs`。普通网页笔记可以没有时间戳。 |
| 逐字稿和总结 | 第二轮的 `Transcript` 按 Session 与来源保存，时间戳对应原视频，并记录来自原视频字幕还是 ASR。用户主动生成的课程总结使用该资料当前已有的逐字稿和笔记。 |

例如，同一节课的直播和回放可以放在一个 `Resource` 下，各有自己的地址和时间轴。时间戳笔记引用实际来源。跨来源跳转需要明确的时间映射。

### 决策 1：网页来源的识别与去重（已确认）

1. 插件收藏时取当前标签页地址和页面标题。Web 粘贴时取用户提交的地址。保留原始 URL 供用户重新打开。
2. 能识别视频时，在同一账号内用「平台 + Platform Video ID + 必要的分集标识」匹配来源。可忽略已知的分享和追踪参数，保留能区分分集的参数。分享短链只有在能确认对应网页和媒体标识时才按视频身份匹配。
3. 无法识别视频身份时，按相同网页地址去重。标题用于展示、搜索和人工判断，同名页面仍可分别收藏。
4. 两条地址疑似指向同一视频且无法确认时，允许分别收藏，由用户归类后自行删除。不同分集各自保存进度，时间戳笔记关联其实际来源。

验收样例：同一分集的普通链接和可识别的分享链接返回同一来源。相同视频页的两个不同分集各有续播位置。两个同名且身份无法确认的页面可以分别收藏。

## 决策 3：指定邮箱邀请与验证码登录（已确认）

项目方预先登记受邀者的邮箱，并手动把试用网址发给对方。受邀用户在 Web 输入该邮箱后，由系统发送登录验证码。首次验证开通试用，之后仍通过邮件验证码登录。试用网址转发后，资格仍归原先登记的邮箱。

### 插件账号关联（已确认）

打开未授权的插件时只展示授权引导。用户从插件打开 Web 授权页，在已登录的 Web 账号下确认关联。Web 尚未登录时，先完成邮件验证码登录，再回到授权页。授权成功后，插件以该账号运行。

有效授权是全部插件功能的前置条件。首轮覆盖收藏、续播和笔记，第二轮的在线音频采集沿用同一门槛。授权缺失或失效时，侧栏和工具栏入口都进入授权流程。验收覆盖未登录、已登录但未确认关联、确认后正常使用，以及授权失效后回到授权引导。

### Web 与插件联动退出（已确认）

同一浏览器配置中，完成关联的 Web 与插件作为一组登录。用户在任一端主动退出时，服务端使这组凭据同时失效。已打开的两端切回未登录状态，插件停止记录播放进度及正在进行的在线音频采集。重新使用时先登录 Web，再授权插件。联动范围按这次浏览器关联确定。

验收时分别从 Web 和插件退出。两端界面都切回未登录状态，旧凭据访问受保护接口均被拒绝，随后可以重新登录并关联。

## 决策 4：播放进度的开始与收尾（已确认）

用户在已授权的插件中点击「开始学习」，才从所选视频的当前播放位置开始记录。用户可以先收藏、打开或试看片段，这些动作本身不写入进度。记录期间可向前或向后拖拽，续播位置按实际播放时间轴更新。保存的是最后播放位置，跳过的区间不计作已看内容。

已有进度时，由用户在插件里选「继续学习」或「从头开始」。插件根据选择定位到上次位置或视频开头，用户主动开始学习后才记录本次进度。

同一个视频可以分多次学习。每次点击「开始学习」开启一个 Session，历史进度和笔记仍归同一个来源。点击「结束学习」结束本次 Session，课程可以以后接着学。播放器暂停时保存当前位置，恢复播放后继续同一次记录。

插件面板提供已打开的课程标签页列表。用户在面板里直接选择目标，可以留在当前浏览器标签页，选中的标签页也可以在后台。随后点击「开始学习」，插件绑定该目标。记录期间锁定目标，即使用户浏览其他标签页，记录仍归原标签页。结束本次学习后，列表恢复可选。视频播完、标签页关闭，或同一标签页导航到不同视频及分集时，原 Session 自动收尾并保存该来源最后已读到的播放位置。

验收样例：A、B 两个课程标签页同时打开。用户留在 B，从插件列表选后台的 A 并开始学习，插件记录 A，列表保持锁定。结束 A 后直接在列表选 B。以后回到 A 时可从上次位置继续，开启新的 Session，历史资料仍归 A。

### 字幕优先、音频转写补位（已确认）

同一课程的多次学习各自产生带来源时间戳的 Transcript。结束单次 Session 收尾并保存本次内容。跳过或未取得文本的时间区间与已有内容分别呈现。

B 站和 YouTube 的视频有可用字幕时，插件优先读取字幕并直接提交给 API。字幕不可用时，再走插件采集音频、API 调用 Worker 的路径。归档使用统一的逐字稿结构，字幕路径无需调用 ASR。两条路径共享资料、Session 和来源标识，以便后续扩展站点。

小鹅通和小红书在一期按 ASR 路径处理。小鹅通 ASR 和旧 YouTube Digest 的字幕采集是已有基线，仍需在新链路联调。基建完成后按三组追加验证：小红书 ASR、B 站字幕、B 站与 YouTube 无可用字幕时的 ASR。

插件读到可用字幕后直接显示字幕全文。ASR 模式沿用 PoC 的分段展示节奏，以约 30 秒音频为一段，每段结果返回后即显示。等待本段结果时，插件显示「转写中」。归档的逐字稿可在 Web 学习库回查。

**同一视频区间只采用一种方式（已确认）。** 字幕内容不全时，字幕路径按原样归档，用户可主动选择「强制转写」，使整个选定区间走 ASR。系统按单一路径归档该区间，字幕缺口由用户决定是否重走转写。

恢复 YouTube 字幕采集时，优先评估复用独立 `youtube-digest` 仓库的 `captions.js`、`content.js` 中的字幕采集逻辑与相关测试，再适配到当前插件的 Source Platform。原 PoC 移除 YouTube 特定逻辑的历史见 [ADR 0001](adr/0001-independent-repo.md)。实现回接时按产品化后的范围更新现有插件发布检查。

**音频采集授权在原视频页和浏览器插件完成（已确认）。** 用户从插件列表选择目标标签页，按浏览器要求在插件和原视频页完成采集授权。此处的浏览器授权独立于 Web 上的插件账号关联。

第二轮开始学习时，插件向 API 提交所选视频的来源。API 按当前账号创建或匹配学习资料和来源，再开启本次 Session。插件提交字幕文本或采集音频。API 直接归档字幕，或调用录播转写 Worker 并保存返回的逐字稿。续学开启新的 Session，已收藏的资料及历史进度、笔记、逐字稿继续归到同一资料。Web 学习库通过 API 管理和展示这些学习记录。

用量与收费为后续功能。API 按账号和 Session 记录转写时长与相关计算用量，Web 学习库提供查询用量和账单的入口。计费口径和价格另定。

Chrome `tabCapture` 对目标标签页有授权要求，须实测从列表选择后台标签页后，浏览器要求用户完成哪些步骤。[Chrome tabCapture 文档](https://developer.chrome.com/docs/extensions/reference/api/tabCapture/)

### 用户主动生成课程总结（已确认）

课程页提供「生成总结」。用户点击后，系统使用该课程当前已有的逐字稿和笔记生成总结，成功后显示。课程是否学完、Session 是否结束都不是生成条件。后续积累了新内容，用户可以再次点击生成。只有用户发起生成操作才创建新的课程总结。

## Web 和插件接口

以下是首轮 `/v1` 接口草案。Web 与插件各持自己的凭据，关联后同组生效和撤销。API 从有效凭据解析账号，按账号校验资料、来源和笔记的归属。

| 阶段 | 接口 | 契约与验收条件 |
| --- | --- | --- |
| 第一轮 | `POST /v1/resources`、`GET /v1/resources`、`GET /v1/resources/{id}` | 粘贴或收藏网页时提交 `url` 和可选 `title`，返回 `resourceId` 与 `sourceId`。服务端检查 URL 类型，账号内重复收藏返回同一条资料。资源详情返回可打开的原地址、来源进度和笔记。 |
| 第一轮 | `POST /v1/sources/resolve` | 插件提交当前网页地址及已识别的平台视频 ID 和分集标识，按决策 1 返回当前账号下的匹配来源或无匹配。 |
| 第一轮 | `PUT /v1/sources/{id}/progress`、`POST /v1/resources/{id}/notes` | 进度提交 `positionMs` 与预期版本，过期写入返回冲突和当前版本。笔记使用客户端生成的请求标识支持重发，可选来源与时间戳。Web 或插件可从详情读回结果。 |

学习库在新标签页打开原地址，插件通过当前媒体匹配已有来源，并提供继续或从头开始的选项。没有插件时，网页仍可打开，用户也能手动保存和查阅笔记。通用收藏无需由服务端访问第三方网页。没有标题时可先存链接，再手动补标题。

## 开发依赖与集成顺序

1. **先定第一轮共享契约。** 一个会话负责确认 `Resource`、`Source`、进度和笔记的最小结构。样例覆盖通用网页、四站可播放视频和 B 站多分集及等价地址。四站复用同一套来源匹配与进度接口，各自验证来源识别和播放器的读写行为。共同固定未登录、跨账号、重复收藏和过期进度写入的响应。
2. **Web、插件与 API 可以并行。** 三条线在各自分支和 worktree 开发，Web 和插件先用同一份接口样例跑通。API 负责人维护数据迁移和公共契约，跨端接口变更先合入集成分支，再让两端同步。第一轮联调通过后进入第二轮。
3. **第二轮复用标签页选择和来源身份。** 分别验收字幕直归档，以及插件采集音频、API 调用 Worker、Web 查询逐字稿。音频路径先实测后台标签页的采集授权。
4. **第三轮复用已归档的逐字稿和笔记。** 验证课程尚未学完时可以主动生成总结，后续可以重新生成，并用另一门课程检查内容隔离。

| 集成门槛 | 最小完整路径 |
| --- | --- |
| 第一轮验收 | 受邀账号登录 Web 并授权插件。用小鹅通、B 站、YouTube 和小红书各一条可播放并可定位的网页视频，分别验证收藏、点击「开始学习」后记录进度、插件里选择续学或从头开始，以及手写时间戳笔记。另验收 B 站多分集独立进度、普通网页和小红书图文收藏、授权门槛和双账号隔离。 |
| 第二轮验收 | 验证字幕全文显示与直归档、ASR「转写中」提示与约 30 秒一段的结果展示、字幕不全时的整段强制转写。同一区间只采用一种方式。两类结果都能在 Web 回查，并验证选定标签页、来源、账号和 Session 归属。 |
