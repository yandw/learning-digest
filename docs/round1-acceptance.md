## 2. 人工验收步骤

### 2.0 环境准备（一次）

1. [ ] 集成分支 tip 合入本文档版本；Chrome 打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序，选仓库根目录；卡片显示版本 **0.2.7**
2. [ ] **API 启动前**登记受邀邮箱（服务端把邀请名单读进内存，启动后用 CLI 登记不会被运行中的服务看到）：

   ```bash
   node apps/api/scripts/invite.js add user1@example.com user2@example.com
   node apps/api/scripts/invite.js list   # 确认两条
   ```

   双账号隔离（§2.7）需要两个邮箱，各配一个 Chrome 用户配置（profile）——插件凭据组按浏览器配置生效。
3. [ ] 启动后端与 Web（两个终端）：

   ```bash
   cd apps/api && npm start        # 127.0.0.1:8787，默认即可
   cd apps/web && npm start        # 127.0.0.1:8080，默认上游即 8787
   ```

4. [ ] 验证码读取方式（dev 邮件实现，尚无真实邮件账号）：API 进程 stdout 会打印 `[mailer] to=… code=…`，同时追加写入 `apps/api/data/outbox.jsonl`
5. [ ] 四站样本各一条**可播放、可拖拽定位**的网页视频（样本登记表见 §3，等待项目方提供）；另备：一个普通网页、一篇小红书图文

## 4. 已知限制与偏差

契约级裁量的完整记录在 [contracts/decisions.md](../contracts/decisions.md)（D1–D8），与实现一致：

- **P10 范围限制已由 P10b 补齐**：P10 交付时「开始学习 + 进度」仅小鹅通开放（page-bridge 位置流当时只覆盖 xiaoe）；P10b 把 B 站 / YouTube / 小红书视频页接入位置流、seek 与播完收尾，四站视频页现均可开始学习（startable）。
- **D1 · 无服务端 Session**：第一轮进度按（账号， Source）单条保存，多次学习服务端只留最后位置；Session/Transcript 契约随第二轮落。
- **D2 · 跨账号一律 404**：不向调用方透露资源存在与否，§2.8 按此验收。
- **D5 · 收藏即一条 Resource + Source**：B 站多分集是列表里多条资料、各有独立进度；自动归组待验证收藏心智后补。
- **D6 · 小红书图文按归一化地址匹配**：视频笔记才有 platformVideoId；图文换分享 token 仍去重，`/explore/` 与 `/discovery/item/` 两形态会重复，留给用户整理。
- **D7 / D8**：小鹅通身份含商店子域（platformScopeId）；纯短码分享链（b23.tv、xhslink）按地址匹配，可能产生重复收藏，属预期。
- **回拖合法**（D4）：进度不做位置单调钳制，按最后实际播放位置保存，跳过区间不计已看。
